Proyecto: `[PROJECT_NAME]` · Fuente de verdad: `docs/phase0/00-decisions.md`
Regla: ninguna fila se marca `IMPLEMENTADO`/`PARCIAL`/`MOCK` en código. Solo `PENDIENTE` (código no iniciado) o `DISEÑADO` (decisión/documento Fase 0 existente). Etiquetas `REQUIERE PROVEEDOR` / `REQUIERE LICENCIA` se usan en la columna de estado cuando el requisito es inalcanzable sin externo.

## Convenciones

- **ID:** `REQ-001…REQ-132`. Estable, trazable a apartados 1–73 del prompt maestro.
- **Prioridad MoSCoW:** `MUST` / `SHOULD` / `COULD` / `WON'T` (en este horizonte).
- **Fase:** `0` (decisiones/docs) · `1` (foundation: gateway/identity/audit) · `2` (accounts/wallet/ledger/notifications) · `3` (market-data/charting/WS) · `4` (trading/OMS/EMS/margin/risk) · `5` (productos avanzados: sintéticos/CFD/bots/copy/backtesting) · `6` (pagos/KYC/P2P) · `7` (backoffice/CRM/support) · `8` (hardening: HA/performance/i18n/seguridad avanzada) · `9` (live readiness: legal/licencias/corte). `MVP` = conjunto mínimo operable en `DEMO` (fases 1–5 parciales + 7 mínimo).
- **Estado inicial:** `PENDIENTE` o `DISEÑADO`. Nada de código existe al cierre de Fase 0.
- **Criterio de aceptación (CA):** verificable por test, inspección, contrato o checklist. No es promesa de implementación.
